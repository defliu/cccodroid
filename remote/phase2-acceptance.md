## 二、mock 环境的浏览器验收（A：过滤）

环境：relay（127.0.0.1:3012）+ `remote/test/mock-gateway.mjs`，浏览器打开同源 PWA。mock 网关在每轮回复里夹带另一会话的后台 `delta`（`[s-notes] …` / `[s-quant] …`），用来检验过滤。

| 操作 | 结果 | 证据 |
|---|---|---|
| 连接后保持「新会话」 | 全量接收 | mock 日志 `watch … (all)` |
| 下拉选 `s-quant` | 只显示 s-quant 的输出，s-notes 的后台行不出现 | `watch … s-quant` |
| 下拉切 `s-notes` | 只显示 s-notes 的输出，s-quant 的行不出现 | `watch … s-notes` |
| 切回「新会话」 | 两个会话的输出都恢复 | `watch … (all)` |
| 刷新 / `run_end` 后 | 下拉选择保持不变，后台行仍可见 | 修复后回归，见下 |

**验收中发现的问题（已修复，`ec90de7`）**：`run_end` 会触发一次 `list` 刷新；`renderSessions` 在用户选了「新会话」时，会把下拉框自动改回「当前项目」的会话 —— 用户没动下拉框，`watch` 却在刷新后自己变严，后台会话的输出被静默过滤。现在只有首次拿到列表才自动选中当前会话，刷新一律保留用户选择（包括「新会话」）。

## 三、真实网关 + 双设备验收（B：多设备）

环境：本机 Windows（`process.getuid` 垫片）+ 临时 home，网关拨号到 127.0.0.1:3012 的 relay；两个独立 Node 客户端（等价于两台 PWA）用同一配对码先后接入。

- 客户端输出：两台各自收到自己的 `ready` 与 `watching` 回执（一台 `sessionId:"s-notes"`，一台 `sessionId:null`），互不影响。
- 网关日志（节选）：

```
20:40:09 [remote] 远程端已加入: 20e794aee678（共 2 台）
20:40:09 [remote] 端到端加密已建立: 20e794aee678（共 2 台）
20:40:09 [remote] 设备 20e794aee678 收全部会话的事件
20:40:10 [remote] 远程端已离开: ba698ef45a2c（剩 1 台）
20:40:25 [remote] 远程端已加入: 9f8384f1ad33（共 2 台）
20:40:25 [remote] 设备 9f8384f1ad33 只收会话 s-notes 的事件

20:41:55 [remote] 远程端已离开: 9f8384f1ad33（剩 0 台）
```

  两台同时在线且筛选各自独立；任一台加入 / 离开都不触发另一台重握手或掉线。

- 设置页 → 远程控制（`/api/remote/status`，页面实时读取）：

| 台数 | 状态文案 | class |
|---|---|---|
| 0 | 已连接中继，等待远程设备接入 | `prov-state` |
| 1 | 远程设备已接入 | `prov-state ok` |
| 2 | 已接入 2 台远程设备 | `prov-state ok` |

  注：状态轮询只在「远程控制」分类打开时进行；后台标签页定时器会被浏览器节流，切走再切回可立即刷新。

## 四、Android 真机清单（待执行）

1. **打包安装**：`scripts/build.sh` 出 APK 并安装；确认 `gw/remote-filter.mjs`、改后的 `gw/remote.mjs` 与 `web/app/10c-remote.js` 随目录进包。
2. **生成配对**：手机 设置 → 远程控制 → 开启，复制配对链接。
3. **设备 1**：电脑浏览器打开配对链接 → 「已加密连接」，下拉出现手机上的会话；选中一个会话应先显示最近的历史消息，顶部「加载更早」能往前翻。
4. **状态（1 台）**：手机设置页显示「远程设备已接入」（绿色）。
5. **设备 2**：另一台手机 / 浏览器打开同一链接 → 手机设置页变「已接入 2 台远程设备」；两台都能各自拉到会话列表。
6. **过滤（核心）**：手机端准备两个会话 A、B。设备 1 选 A、设备 2 选 B，分别发一条消息 → 各自只看到所选会话的流式输出，**不串台**。
7. **后台负载时不串台**：让 A 持续输出（跑一个长任务），设备 2 停在 B → 设备 2 不应出现 A 的流式行。
8. **新会话语义**：设备 1 切到「新会话」发消息 → 本轮应实时可见（fail-open），且列表刷新后下拉不会被顶回旧会话（`ec90de7` 的行为）。
9. **单台断开**：设备 1 断网 / 关页面 → 设备 2 不受影响；手机设置页台数变 1，回到「远程设备已接入」。
10. **上限（可选）**：第 5 台设备无法加入（中继 4 peer/房间）；第 4 台正常。
11. **权限卡（D）**：让手机跑一个需要确认的 Bash 命令 → 远程出现卡片；点「允许」→ 手机端继续执行；再触发一次点「拒绝」→ 手机端显示被拒绝。不操作等超时 → 卡片显示「⌛ 超时未答，按拒绝处理」，手机端也按拒绝继续。
12. **始终允许（D）**：带 suggestions 的请求点「始终允许」→ 该规则出现在手机端允许列表（后续同类请求不再询问）；确认远程不能自定义规则。
13. **文件浏览（E）**：远程打开「文件」→ 工作区列表与手机工作区一致；打开一个文本文件与一张图片；在文本里点「继续读取」；路径越出工作区时应提示无法访问。
14. **上一级（E）**：子目录内点「上一级」回到根；根目录时按钮不可用；远程禁用后文件面板自动关闭。

## 八、已知限制（不属缺陷）

- 同一房间共用一个配对码 = 同权限；无按设备吊销，遗失设备只能「重新生成配对码」全量踢出（按设备配对在 Phase 2 D 一起考虑）。
- 远程审批权限 = 把本机操作权交给配对码持有者：没有二次点击确认，也没有按设备配对；遗失设备时请重新生成配对码。
- 文件浏览只读：文本「继续读取」每页展示从 `next` 开始的内容（不累积）；blob 单文件上限 5 MB；密钥过滤按文件名/目录名单，工作区里的其它内容对已配对设备可读。
- 「新会话」视图不做严格过滤（fail-open）：新会话在拿到 sessionId 前的事件无法归属，严格过滤会藏掉用户刚发的那一轮。
- 「新会话」视图不做严格过滤（fail-open）：新会话在拿到 sessionId 前的事件无法归属，严格过滤会藏掉用户刚发的那一轮。
- 历史回放只发白名单字段：没有 thinking 与 hook 上下文，正文 8 KB、工具入参/结果 4 KB、整页 120 KB 封顶，超出的部分截断；翻到最早一页后不再自动续读，新内容由实时事件流负责。
- 中继 4 台/房间、80 条/10 秒/连接、单帧 256 KB 均为 Phase 1 已定参数，本次未改。
